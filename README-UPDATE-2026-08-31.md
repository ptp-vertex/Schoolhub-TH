# SchoolHub — สรุปการปรับปรุงการส่งออก 31 สิงหาคม 2026

รอบนี้ปรับรายงานงานขาดตามภาพตัวอย่างที่แนบมา โดยคง **เปอร์เซ็นต์งานขาดเดิม** ไว้ และเพิ่ม **เปอร์เซ็นต์ความคืบหน้าเฉพาะในไฟล์ส่งออก** ไม่เปลี่ยนความหมายของข้อมูลในกล่องแชร์นักเรียน

| ส่วนที่ปรับปรุง | รายละเอียด |
|---|---|
| เปอร์เซ็นต์งานขาดเดิม | ยังแสดงเป็น `งานขาด ÷ งานที่ติดตาม × 100` ในหน้าติดตาม กล่องแชร์ และรายงานส่งออก |
| เปอร์เซ็นต์ความคืบหน้า | เพิ่มเฉพาะรายงานส่งออกเป็น `งานที่ทำแล้ว ÷ งานที่ติดตาม × 100` พร้อมจำนวนงาน เช่น `คืบหน้า 29.4% · 5/17 งาน` |
| รูปภาพ | ออกแบบใหม่ให้มีหัวรายงานอินดิโก การ์ดแยกรายคน แถบสรุปงานขาด/ความคืบหน้า และตาราง 3 คอลัมน์ที่ล็อกตำแหน่ง |
| PDF | สร้างหน้า A4 แยกรายคน/กลุ่มรายการ ไม่ใช้ภาพยาวแล้วตัดกลางหน้า ทุกหน้ามีหัวตาราง `สัปดาห์ / รายการงานที่ยังขาด / สถานะ` ซ้ำ และมีเลขหน้า |
| ฟอนต์ | โหลดและรอ `Noto Sans Thai` ก่อนเรนเดอร์ พร้อม `font-synthesis: none`, `overflow-wrap` และคอลัมน์แบบ `minmax(0,1fr)` เพื่อกันตัวหนังสือเลื่อน/ซ้อน |
| ขนาด | ลดขนาดหัวข้อ รายการ และป้ายสถานะให้กะทัดรัดขึ้น แต่คงชื่อผู้เรียน/ชื่องานให้อ่านได้ชัด |
| จำนวนรายการ | รองรับรายการทั้งหมด ไม่จำกัด 13 รายการ และ PDF แบ่งเป็นชุดละ 16 รายการต่อหน้าสำหรับผู้เรียนที่มีรายการมาก |

## การลบ hash URL ทั้งเว็บไซต์

ระบบเดิมใช้ `#sh-link-*` เป็น fragment สำหรับติดตามการกดปุ่มภายใน แม้ไม่ใช่เส้นทางของหน้าเว็บ แต่ทำให้เครื่องหมาย `#` ปรากฏท้าย URL รอบนี้เปลี่ยนทุกจุดให้ใช้ `window.location.pathname + window.location.search` ผ่าน History API แทน และเพิ่มการล้าง fragment เก่าทันทีเมื่อเปิดแอป ลิงก์เดิมที่มี hash จึงถูกทำให้เป็น URL สะอาดโดยไม่ต้องรีโหลดหน้า

การล้างนี้ไม่ลบ query parameters ที่ใช้กับลิงก์แชร์หรือการรีเซ็ตรหัสผ่าน และไม่ได้แก้ `server/` หรือฐานข้อมูล

## หมายเหตุ

การสร้าง PDF ใช้ภาพของแต่ละหน้า A4 ที่สร้างแยกจากข้อมูลรายคน จึงไม่เกิดปัญหาภาพยาวถูกตัดกลางหน้า และไม่เกิดการวาดข้อความซ้ำจากการเลื่อนภาพเดิมขึ้นลง แต่ละหน้าใช้หัวตารางของตัวเองเพื่อให้เปิดดูหรือพิมพ์แยกหน้าได้ง่าย

หากไม่มีงานที่ติดตาม ระบบแสดง `—` แทนเปอร์เซ็นต์เพื่อไม่เดาค่า ข้อมูลทั้งหมดมาจากตัวกรองและข้อมูลจริงในระบบ ไม่สร้างข้อมูลตัวอย่างถาวร และไม่แก้ไข `server/` หรือฐานข้อมูล

ผู้ใช้ควรทดสอบกับชื่อผู้เรียน/ชื่องานภาษาไทยที่ยาวและข้อมูลจริงจำนวนมากอีกครั้งก่อนใช้งานจริง
